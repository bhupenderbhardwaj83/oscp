Half page

Install

Put oscp on the PATH

Do this once, from the directory that contains the oscp launcher. That launcher is a shell script. oscp.py is the program it runs.

the install
./oscp setup
exec $SHELL
  1. oscp setup creates ~/.local/share/oscp/venv if it is missing. It does not install packages. The program uses the Python standard library.
  2. It points ~/.local/bin/oscp at the launcher in this directory.
  3. If the shell rc does not already contain oscp shell-init, it appends the Tab-completion line. zsh, or an empty SHELL, writes ~/.zshrc. Anything else writes ~/.bashrc. If ~/.local/bin is not on PATH at that moment, it appends a PATH line too.
  4. exec $SHELL loads that line. A terminal that is already open keeps the old Tab menu until you do this, or open a new one. The commands themselves read oscp.py on every run, so they do not wait for the new shell.

Running oscp setup again is safe. An existing venv is left in place, the launcher is linked again, and a completion line that is already there is not added twice.

If you would rather edit the rc yourself:

manual link
ln -sf "$(pwd)/oscp" ~/.local/bin/oscp
echo 'eval "$(command oscp shell-init zsh)"' >> ~/.zshrc
exec zsh

Bash is eval "$(oscp shell-init bash)" in ~/.bashrc. ~/.local/bin has to be on PATH. The launcher uses the venv Python when ~/.local/share/oscp/venv/bin/python3 exists, and python3 otherwise.

This page's keys are not the terminal's keys. Here, ↑↓ move between nodes, Enter opens the half page, Esc closes it, / focuses search inside that page, and ⌘B or CtrlB collapses the sidebar. Use the program only on machines you own or are allowed to test. Replace TARGET, LHOST, LPORT, and USER before you paste a command into a shell.

Any page

How a screen behaves

Every feature below uses the same screen. Learn it once.

  1. If the text is longer than the terminal, and both input and output are a terminal, it starts at the top. Enter is one line. Space or Tab is one page. q, Ctrl-C, or Ctrl-D leaves. A page that fits prints at once.
  2. Numbered output then waits. Type 3, a range 3-5, or 3,7. The copy drops the line number, a leading $, and a trailing # note. o 7 opens an http or https URL that is on line 7. Enter on an empty line leaves. On a long numbered page, c opens that prompt before the end.
  3. On a Mac the copy uses pbcopy. On Linux it tries wl-copy, then xclip, then xsel. If none of those exist, it says so and copies nothing.
  4. A red ! on a line means that command can delete files, change permissions or ownership, stop a process, overwrite a disk, or rewrite git history. The word after the mark says which.
  5. On a decision menu, Tab marks at most three choices and leaves every other row where it was. Three stars are magenta, two are yellow, one is amber, and only when the terminal has color and NO_COLOR is unset. The catalogs of technique ids and of atlas tool names are not marked. tmux and shell-script sections are not marked.
  6. OSCP_NO_PICK=1 skips the copy prompt. Output that is not a terminal prints the whole text and does not page. NO_COLOR=1 turns color off. It does not, by itself, turn the pager off.

Exam

Where you are, then the next command

Open this when you have a machine and you need the phase, not a tool tour. oscp howto prints the whole loop. oscp howto recon prints one phase. The write-up behind the loop is oscp technique show full-workflow.

start the machine
export TARGET=10.10.10.10 ; export LHOST=10.10.14.5
oscp technique show target-variable
oscp howto
oscp howto recon

The addresses above are the reminder oscp howto prints. Replace them. If a phase sits still for about 20 minutes, the map says to drop back a phase and enumerate, and it points at oscp technique show stuck-checklist.

1. Recon — find every service

Full port sweep, then enumerate each service deeply. Map every open port to a plan.

run these
oscp technique show recon-walkthrough    # exact nmap passes + the port->service->plan table
oscp atlas nmap    # tool reference (also: rustscan, masscan, autorecon)
oscp cmd recon    # recon cheat-sheet category
oscp cmd dns    # if 53 is open
2. Service — attack what's open

Pick the plan for each open port; test every input until something gives a way in.

run these
oscp technique show attack-http    # 80/443 -> wordpress / php-apache / react branches
oscp technique show attack-ftp    # 21
oscp technique show attack-ssh    # 22
oscp technique show attack-smb    # 139/445
oscp technique show attack-rdp-winrm    # 3389 / 5985
oscp technique show attack-databases    # 3306 / 1433 / 5432 / 6379 / 27017
oscp technique show web-methodology    # the source->sink bug-hunting mindset
oscp cmd web   ·   oscp cmd smb   ·   oscp cmd services    # quick cheat-sheets
3. Foothold — turn the bug into a shell

Start a listener, fire a reverse shell in the target's language, and catch it.

run these
oscp technique show foothold-logic    # the full webshell -> reverse-shell flow
oscp hacktools listener 4444    # start the catcher FIRST
oscp hacktools revshell $LHOST 4444    # pick a reverse shell (LHOST filled in)
oscp hacktools php   ·   oscp hacktools windows   ·   oscp hacktools msfvenom    # by target type
oscp cmd shells    # shells cheat-sheet
4. Stabilise — get a real TTY

Upgrade the dumb shell so you have job control, history and arrow keys.

run these
oscp technique show shell-tty    # the python-pty + stty raw upgrade, step by step
oscp atlas rlwrap   ·   oscp atlas pwncat-cs    # nicer shell handling
5. Enumerate — local recon as the new user

Grab the first flag, run the enumerator, hunt and reuse credentials.

run these
oscp technique show post-foothold-enum    # the first 10 minutes on a box
oscp technique show linux-enum-checklist    # or: windows-privesc-checklist
oscp atlas linpeas   ·   oscp atlas winpeas    # the automated enumerator
oscp technique show creds-hunting    # find creds, then reuse them everywhere
oscp hacktools transfer $LHOST $LPORT linpeas.sh    # get tools onto the box
6. Escalate — root / SYSTEM

Map each enumeration finding to the technique that escalates it.

run these
oscp technique show privesc-linux-path    # finding -> technique decision tree
oscp technique show privesc-windows-path    # the Windows equivalent
oscp gtfo <binary>    # sudo / suid / capability abuse by binary
oscp cmd privesc-linux   ·   oscp cmd privesc-windows   ·   oscp cmd ad    # cheat-sheets
7. Loot & proof — capture and pivot

Prove each flag properly, loot credentials, and pivot to any further hosts.

run these
oscp technique show flags-and-proof    # local.txt/proof.txt + whoami+ip screenshot + submit
oscp cmd creds    # dump and crack what you find
oscp cmd pivot    # reach deeper hosts (chisel / ligolo / ssh tunnels)
oscp technique show ssh-tunneling-patterns    # -L / -R / -D decoded
8. Report — the write-up that scores

A reproducible per-machine report. Points come from the report, not the shell.

run these
oscp technique show report-writing    # structure + what each machine section needs
oscp technique show note-taking-reporting    # how to take notes as you go
oscp technique show oscp-exam-strategy    # exam: time, scoring, the 15-min rule

Shorter words open a phase. scan and nmap open recon. shell opens foothold. privesc opens escalate. oscp alias lists the rest. map, tool, tools, utility, commands, cmds, and overview open oscp howto map, which is this same "what to open" list, in the terminal.

Technique

The write-up

Open this when you need the reason, the order, or a checklist. It is three shelves: path (the exam in order), a topic such as windows or web, and notes (the 0xsyr0 sheet).

  1. oscp technique lists the shelves.
  2. oscp technique path is the exam in stage order. oscp methods still opens that library.
  3. oscp technique windows is one area. Use the topic name you saw in the list.
  4. oscp technique show kerberos-flow is one write-up. Type a line number to copy a command on it. The same id on two shelves prints both.
  5. oscp technique search kerberos is how you find the id.
  6. oscp technique notes lists the 0xsyr0 sections. oscp technique notes post-exploitation prints one.
  7. Tab after oscp technique show, with nothing typed after show, pages the ids. Enter is a line, Space is a page, q goes back. A few letters and then Tab filters instead. oscp tech show, oscp tec show, and oscp teq show do the same. This is shell completion, so the shell-init line has to be loaded.
a write-up
oscp technique path
oscp technique show kerberos-flow
oscp technique search kerberos

Atlas

One tool

Open this when you already know the tool and you want the syntax, what each part means, and real invocations. You do not open it to decide which tool.

  1. oscp atlas lists the tools. oscp atlas ffuf is one tool: syntax, description, anatomy, origins, and use cases.
  2. A line number copies that use case. o plus the line number opens a docs URL when the line has one.
  3. A second word narrows the page to matching use cases: oscp atlas git log.
  4. oscp atlas search passwd searches names and use cases when you do not know the tool's name.
  5. A few tools answer to another name. oscp atlas netcat opens nc. oscp alias lists those names. crackmapexec is its own page.

Short commands

The line you paste

Open this when the write-up is done and you want the command. oscp cmd with no category lists them. A category prints numbered lines. You type the number.

a category
oscp cmd
oscp cmd privesc-linux

oscp cmd web and oscp cmd web basic are the same enumeration page. A second word is only valid after web: php, wp, tomcat, jenkins, iis, joomla, drupal, git. oscp cmd php opens that page. oscp cmd basic does not. oscp cmd wordpress opens the WordPress page. oscp cmd ssh is the SSH category, not a web page.

oscp list, oscp show, and oscp copy still run. The name on the menu is cmd.

Payloads

Build it, then catch it

Open this when the bug is already there and you need a listener, a reverse shell, a webshell, or an encoding. Start the listener before the shell. The foothold phase prints these two lines.

catch, then send
oscp hacktools listener 4444
oscp hacktools revshell $LHOST 4444

The categories are revshell, listener, php, webshell, tty, transfer, msfvenom, lfi, xss, sqli, linux, and windows. oscp hacktools php, oscp hacktools windows, and oscp hacktools msfvenom are the other foothold picks. oscp hacktools transfer $LHOST $LPORT linpeas.sh is the enumerate-phase line for getting a file onto the box.

encode, decode, hash, and obfuscate are different. They read the argument, a pipe, or stdin, and they copy the result. They do not use the line picker, because they may be waiting on stdin. oscp hacktools hash apple is the plain form. For a string with quotes, pass it on stdin.

Binaries

A sudo, suid, or capability binary

Open this when enumeration has named a Unix binary and a context: sudo, suid, or a file capability. It is not the place to learn privilege escalation from nothing. That write-up is oscp technique show privesc-linux-path.

  1. oscp gtfo tar shows every technique for that binary.
  2. oscp gtfo tar sudo keeps one function or one context.
  3. Type the line number of the technique you will paste.
  4. oscp gtfo search finds a binary by name. oscp gtfo list lists them. Those two are the marked Tab choices. The binary names themselves are not starred.

Search

When you do not know the command

A search with no shelf looks across the short commands, the path, the write-ups, atlas, GTFOBins, the notes, and the bash snippets. It prints a short list from each place, and a line that opens the rest of that shelf.

everywhere, then one shelf
oscp search wireless
oscp search atlas passwd

One word that is itself a shelf name still searches everywhere. oscp search atlas does not limit the search. The shelf applies when a term follows.

Shelf words: cheat-sheet (also cheatsheet, cmd), methods (also method, path), manual, atlas, gtfo (also gtfobins), notes (also note), bash (also shell-script, shellscript).

Links

A URL you will open again

  1. oscp bm or oscp bm list shows the tree, best-rated first. oscp bm list offsec is one group.
  2. oscp bm open 18 opens that number. On a Mac it tries Google Chrome first, then the default browser. --browser safari names one. The names are chrome, safari, firefox, edge, brave, arc, and system.
  3. oscp bm find youtube searches names, addresses, notes, tags, and groups.
  4. oscp bm add https://gtfobins.org --group offsec --rate excellent saves a link. Ratings are good, very good, excellent, or 1, 2, 3. A duplicate is refused.
  5. oscp bm rate 18 excellent changes a rating. oscp bm rm 9 forgets one. oscp bm import refs.json reads a ti ref export file, or a text file with one link per line.

ref, reference, and bookmark are the same command. A bookmark's stars are its rating. An unrated bookmark stays as empty stars. Those stars are not the Tab marks from the menus.

The Kali box

The VM, the terminal, a bash file

These three are setup, not a phase of the exam. Use them before the first machine, or when the terminal itself is the question.

once, then as needed
oscp lab-setup
oscp lab-setup vpn
oscp tmux logging
oscp shell-script loops

oscp lab-setup walks the Kali VM on VMware Fusion: vm, install, guest-tools, update, tools, snapshot, vpn, mtu, profiles, gotchas, checks, labenv. One section is oscp lab-setup vpn. The Mac Wi-Fi page it points at is oscp technique show wireless-lab-setup-macos.

oscp tmux is keys, command mode, and logging on this machine. The examples use Ctrl-a. The default prefix is Ctrl-b. oscp cmd tmux is the short list. oscp atlas tmux is the tool page.

oscp shell-script is bash you copy into a file: start, safety, variables, quoting, if, loops, args, functions, arrays, files, redirect, security. The page does not run the snippets. A line number copies one. N-M copies a block.

Other names

When the menu name is not the one you typed

oscp alias prints every one. Tab keeps the main name.

  • tech, tec, and teq open oscp technique. teq appears in Tab only after you type teq.
  • ht opens oscp hacktools. install opens oscp setup.
  • shellscript and bash-script open oscp shell-script.
  • methods, manual, and notes still run. The menu names are technique path, technique, and technique notes.

Modularity

Two kinds of change

A new entry in a data/*.json file is read on the next command. Tab lists ids, tool names, categories, and sections by running oscp __complete, so the completion script stays as it is.

A new command, or a new word on the main menu, is a change to oscp.py and to the script oscp shell-init prints. The leaves on this map are the files that stay independent of that.

manual.json

A write-up

oscp technique show <id> reads data/manual.json. Each entry has an id, a topic that is already on the menu, a title, a brief, tags, and a body.

The body is headings, prose, indented commands, and tables. A bold span stays on one prose line. Indented lines stay plain, so a command block does not carry bold markers.

methods.json

A path stage

oscp technique path reads data/methods.json. That is the exam in stage order. oscp methods still opens the same library.

notes.json

A note section

oscp technique notes lists data/notes.json. oscp technique notes <section> prints one section of the 0xsyr0 sheet.

atlas.json

A tool page

oscp atlas <name> reads data/atlas.json. A page has the syntax, what each part means, and use cases. A second word keeps the use cases that match. A new name shows up in Tab without a new subcommand.

cheatsheet.json

A cheat line

oscp cmd <category> reads data/cheatsheet.json and prints numbered lines. A second word is only valid after web: php, wp, tomcat, jenkins, iis, joomla, drupal, or git.

hacktools.json

A payload

oscp hacktools <category> reads data/hacktools.json. The categories are revshell, listener, php, webshell, tty, transfer, msfvenom, lfi, xss, sqli, linux, and windows. encode, decode, hash, and obfuscate read stdin and copy the result.

gtfobins.json

A binary

oscp gtfo <binary> reads data/gtfobins.json. A second word keeps one function or one context, as in oscp gtfo tar sudo.

howto.json

Phase wording

oscp howto and oscp howto <phase> read data/howto.json. Editing that file changes the terminal. The exam folds on this page are a copy of it, so they change only when this page is rebuilt.

Setup files

A setup section

data/labsetup.json, data/tmux.json, and data/shellscript.json are section lists. oscp lab-setup, oscp tmux, and oscp shell-script read them. A new section is offered in Tab the same way as a new write-up.

oscp.py

A new command

A new menu word is a change to oscp.py and to the completion script it prints. Data files do not need that. After a structure change, regenerate the script, then open a new shell so the rc line loads it:

regenerate
python3 oscp.py shell-init zsh > completions/_oscp

The shell already evals oscp shell-init. This page does not edit the rc.
